# 외주관리 시스템 — 외주관리시스템

> 회사네오 운영 담당 외주 운영 도구. 외주 발주내역과 입고현황을 토대로
> 지금 외주가 어디까지 왔는지 보고 관리합니다.

클라우드 문서 에 있는 발주·실적·단가 엑셀을 **읽기 전용**으로 연동해 외주처별 진행률과
설비 가동 점유율을 집계하고, 부자재 사용기록서 생성부터 월 마감 대조·월 지표 집계까지
한 흐름으로 다룹니다. 기존 엑셀 업무 방식은 그대로 두고 **집계와 문서 생성만 자동화**하는 것이 목표입니다.

## 🔒 소스 저장소는 비공개입니다

이 저장소는 **소개·화면시안·매뉴얼만** 담은 공개 저장소입니다.

실제 소스 코드는 **사내 비공개 저장소**에 있습니다. 사내망 계정이 있어야 접근할 수 있고,
외부에 공개하지 않습니다. 운영 배포도 사내 저장소에서만 일어납니다.

이 저장소에는 다음이 **들어 있지 않습니다**.

- 애플리케이션 소스 코드 · 설정 파일 · 의존성 목록
- 접속 주소, 자격 증명, 환경변수, 시크릿 참조
- 실제 협력사명 · 제품코드 · 수량 · 금액 · 계정 정보 · 사내 조직 정보

화면시안과 매뉴얼에 나오는 모든 수치와 이름은 **고정 시드로 생성한 가상의 값**입니다.
같은 시드를 쓰므로 누가 열어도 같은 숫자가 나옵니다.

실제 데이터로 오해되지 않도록 화면시안에는 표시를 세 겹으로 남겼습니다.

- 화면 전체에 **`예시 데이터 · SAMPLE` 워터마크** — 일부만 캡처해도 함께 찍힙니다
- 대시보드 첫머리에 **예시 데이터 안내 띠**
- 그래프 제목마다 **`예시` 배지**

## 업무 흐름

```
[엑셀] 발주 입력 → 적재 → 부자재 기록서 생성 → 발주 전달(잠김)
                                  ↓
[엑셀] 입고 실적 → 진척 집계 → 마감 대조 → 확정·보관
```

괄호 밖 단계(발주 입력 · 입고 실적)는 시스템 밖 엑셀에서 일어납니다.
부자재 기록서 생성 여부와 메일 전달 여부는 **원본 엑셀에 없는 칸**이라 시스템에서만 관리합니다.

## 설계에서 정한 것

| 항목 | 확정 내용 | 화면에 미치는 영향 |
| --- | --- | --- |
| **데이터 원본** | 클라우드 문서 엑셀이 원본, 시스템은 읽어 적재만 한다 | 조회 화면은 적재된 DB를 읽는다. 입력 화면이 있어도 기본은 잠겨 있다 |
| **기준월** | 적재된 발주번호 `NEO-YYYYMM-` 의 최댓값 | 대시보드에 월 선택이 없다. 새 달 시트가 없으면 지난달이 기준이고 배너에 함께 적는다 |
| **월 선택** | 발주관리는 원본에 있는 월 시트만 탭으로 띄운다 | 드롭다운이 아니라 시트 탭이다. 없는 달은 뜨지 않는다 |
| **동기화** | 날짜가 바뀐 뒤 첫 진입 때 1회 | 수동 동기화 버튼이 없다. 당일 중 원본 변경은 다음 날 반영. 단가표만 수동 동기화 가능 |
| **입고 집계** | 모수는 기준월, 분자는 기준월 이후를 이어서 센다 | 다음 달 시트가 없어도 진행률이 멈춰 보이지 않는다 |
| **로그인** | 회사 계정 단일. 비밀번호 로그인은 로컬 개발 전용 | 로그인 화면에 입력칸이 없고 버튼 하나. 운영에서는 서버가 비밀번호 경로를 막는다 |
| **계정 승인** | 첫 로그인 시 자동 신청, 관리자가 역할을 골라 승인 | 승인 전 계정은 어떤 화면도 열리지 않는다 |
| **금액 노출** | 조회 권한에게는 서버 응답에서 금액을 지운다 | 화면에서 숨기는 것으로 끝내지 않는다. 열 자체가 비어 온다 |
| **공개 설정** | 메뉴 9종 · 세부 기능 7종을 관리자가 켜고 끈다 | 끈 기능의 버튼은 사라지지 않고 자물쇠로 바뀐다 |

## 집계 규칙

모든 화면이 같은 규칙을 씁니다. 두 화면의 숫자가 다르면 자료가 다른 것이지 계산이 다른 것이 아닙니다.

| 항목 | 계산 |
| --- | --- |
| 입고 진행률 | `입고수량 ÷ 발주수량 × 100` |
| 설비 점유율 | `입고수량 ÷ (일 CAPA × 누적 조업일)` |
| 발주 점유율 | `발주수량 ÷ (일 CAPA × 누적 조업일)` |
| 일 CAPA | `Σ (라인수 × CAPA/1라인)` — 설비 10종 |
| 누적 조업일 | 기준월 1일부터 기준일까지의 월~금 일수 |
| 외주금액(실입고) | `최종 입고수량 × 협력사단가` |

- **취소 · 외주처이동은 집계에서 뺍니다** — 옮긴 건은 옮겨 간 쪽에 새 발주로 잡혀 둘 다 세면 두 번 집계됩니다.
- **실적 배분은 FIFO** — 같은 협력사 × 제품코드의 분할 발주에 발주일자 오름차순으로 채웁니다.
- **CAPA 미등록 업체는 분자에서도 뺍니다** — 그렇게 하지 않으면 전체 점유율이 실제보다 높게 나옵니다.
- **표준 설비 10종에 없는 유형은 점유율을 공란으로 둡니다** — 임의 분모를 쓰면 수치가 왜곡됩니다.
- **이월은 표시만 합니다** — 발주를 새로 만들지 않습니다. 마감 종결(종료·사파완료·TECO)은 제외합니다.
- **발주내역에 없는 입고는 표 끝에 따로 적습니다** — 분자에만 잡혀 진행률이 100%를 넘는 이유를 보이게 하려는 것입니다.
- **입고일자에 글자가 섞인 행도 셉니다** — '직납·환입' 같은 메모는 날짜 비교에서 탈락하므로 시트 월로 가려 함께 읽습니다.

| 검증 상태 | 조건 |
| --- | --- |
| 일치 | 외주 수량 = 내부 입고 |
| 수량불일치 | 둘 다 0보다 큰데 값이 다름 |
| 외주누락 | 외주 수량 0 · 내부 입고 있음 |
| 내부누락 | 내부 입고 0 · 외주 수량 있음 |

양쪽 수량이 모두 0인 품목은 표에서 뺍니다.
**정산 금액 = 외주 수량(협력사 마감내역서) × 적용 단가** 이며, 단가가 없으면 0원으로 나옵니다.
**불일치가 남아 있어도 확정은 막지 않습니다** — 확인 창만 띄우고, 차이를 남긴 채 월을 닫아야 하는 경우가 있어
판단을 사람에게 맡깁니다. 확정 내역은 그대로 이력에 남고 재확정할 수 있습니다.

자세한 계산과 예외는 [매뉴얼 13장](manual.html#s13)에 있습니다.

### 월 지표 — 지표마스터 37개

운영관리대장의 지표 정의를 전부 DB 에서 계산합니다. 손으로 세는 칸을 두지 않는 것이 목적입니다.

| 묶음 | 개수 | 다루는 것 |
| --- | --- | --- |
| 운영 | 7 | 서비스 중단, 배포 건수·성공률·소요, 원본 연동 이상일수 |
| 에러 | 11 | 발생·조치 완료·월말 잔여·중단급·반복, 원인 5종 |
| 개선 | 9 | 개선 완료, 구분 6종, 미배포, 운영실측 |
| 이용·처리 | 10 | 이용자 수, 로그인, 화면 조회, 발주·입고·마감 처리, 부자재 생성, ERP 대기, 연동 성공률 |

집계 구분에 따라 연간 계산이 다릅니다 — **상태·누계**는 합, **시점**은 마지막 달 값,
**평균**은 값이 있는 달의 평균, **비율**은 연간 분자 ÷ 연간 분모로 다시 계산합니다.

### 운영에서 지키는 것

- **원본은 시스템이 고치지 않습니다.** 쓰기 기능은 기본적으로 잠겨 있고, 켜도 원본과의 정합은 다음 동기화에서 맞춰집니다.
  예외는 둘 — **마감현황**과 **마감 화면의 적용 단가**는 원본 엑셀에 없는 칸이라 시스템에서만 관리합니다.
- **두 겹 차단.** 화면에서 버튼을 가리는 것과 서버에서 동작을 막는 것을 함께 합니다.
  화면만 가리면 주소를 직접 불러 우회할 수 있습니다. **역할이 설정보다 우선입니다.**
- **작업 기록.** 업무 API 전체에 1계층 감사가 걸려 있고, 생성·수정·삭제·승인·다운로드·권한 변경은
  2계층으로 별도 기록됩니다. DB 조회 같은 읽기도 남깁니다.
- **로그인 보호.** 계정·접속지 각각 5회 연속 실패 시 15분 잠금이며, 실패 사유는 구분해서 알려주지
  않습니다(계정 열거 방지). 세션은 마지막 사용 후 8시간이 지나면 끊깁니다.
- **자기 계정 보호.** 관리자가 스스로를 조회 권한으로 내리면 되돌릴 방법이 없어, 본인 권한 변경과 삭제를 막습니다.

### 차트를 라이브러리 없이 그린 이유

사내망에서 외부 주소가 막히면 CDN 스크립트를 불러올 수 없어 화면이 빕니다.
그래서 대시보드와 일별 현황의 모든 차트를 **SVG 로 직접 그립니다**. 화면시안도 같은 방식입니다.
